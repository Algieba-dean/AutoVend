# 工业级汽车数据湖构建：从零到 6000 款车型、65 大品牌的自动化高并发采集实战

## 1. 业务背景与规模突破

在汽车垂直领域大模型与智能选车系统构建中，底层最关键的基石是**高维度、全生命周期、零遗漏的真实车型参数湖（Data Lake）**。传统爬虫面对易车网等复杂的 SPA 动态单页架构、按需加载虚拟列表与反爬拦截机制，往往只能获取少数几款主销热门车型的静态参数，存在严重的“长尾车型丢失”、“改款年份断层”、“合资/新能源子品牌割裂”等问题。

通过三维动态自发现通道（Brand Hub + MID 树 + 语义搜索路由）、2018~2026 全历年跨年 Payload 穿透合并、自适应生命周期上下文回收（Context Recycling）以及多品牌并发生产级 CLI 引擎，AutoVend 汽车数据湖资产正式实现跨越式突破：

- **品牌总数**：**65 个主流/合资/新势力/超豪华/商用全谱系一线品牌**
- **车系总资产**：**791 个车系**
- **车型总配置**：**5,888 款完整车型（Trims）**
- **参数维度**：**每款车型覆盖 12 大类、200+ 项工业级硬核配置参数（电池容量、续航工况、底盘架构、智能驾驶芯片算力、激光雷达线数等）**

## 3. 高并发与长运行下的稳定性工程架构

在批量处理 65 个品牌、近 800 个车系、近 6000 款车型的长时间抓取链路中，系统面临两大挑战：**内存膨胀与无参数展车异常**。AutoVend 通过以下核心机制保证了无人值守流水线的健壮性：

### 3.1 动态上下文轻量回收（Context Recycling）
Playwright 在长期抓取数百个页面并拦截大型 JSON Payload 时，Chromium 渲染进程与 CDP 会话的内存开销会线性上升。AutoVend 适配器内置了计数器机制：
```python
if self._req_counter >= 15:
    logger.info("Recycling browser context (handled 15 requests)...")
    await self._context.close()
    self._context = await self.browser.new_context(user_agent=self.CHROME_UA)
    self._req_counter = 0
```
每处理 15 次车系级抓取，自动释放旧上下文并秒级热重载全新会话，使整体爬虫常驻内存稳定在 **180MB** 以内。

### 3.2 展车与概念车优雅降级
针对尚未公布配置的未来概念车或展车（API 返回 `None` 或无年份配置树），引擎层引入了安全保护机制，自动记录降级日志而不阻断整个品牌的并发批量抓取队列。

## 4. 数据湖检索与多维分析实战

### 4.1 全库品牌大盘分析 CLI
```bash
uv run python -m src.crawler.cli brand-stats
```
输出各品牌当前车系与车型数量全景看板。

### 4.2 跨品牌全局关键词即时检索
