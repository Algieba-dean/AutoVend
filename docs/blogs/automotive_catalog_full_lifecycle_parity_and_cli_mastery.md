## 1. 行业背景与“数据完备性困境”

在智能汽车导购、汽车大模型评测与全息车型数据库构建中，**“数据资产的完备性与一致性”**是决定系统成败的生命线。

在传统爬虫工程中，开发者往往面临以下三大行业级顽疾：
1. **工程代号黑洞（Slug Quirks & Obfuscation）**：
   - 平台大量使用立项代号或概念车名作为底层 URL，例如：零跑 C10 为 `lingpaob11`（B11代号）、零跑 C11 为 `lingpaocmore`（C-more概念车）、海豚为 `biyadiea1`（EA1代号）、宋L EV 为 `biyadibjichundiansuv`、小米 YU7 为 `xiaomimx11`。手写拼音或规则猜测会导致 100% 出现 404 遗漏。
2. **生命周期割裂与前端折叠（Lifecycle Collapse & Year Truncation）**：
   - 现代汽车垂直媒体（如易车网、汽车之家）的前端普遍采用 SPA 异步渲染，页面首屏默认仅加载最新的 2024~2026 在售年款，历年生产销售过的 2018~2023 款、改款以及停售款被深藏在下拉组件中，导致单车系款型丢失率高达 70% 以上。
3. **前台导购与历史底库脱节（Marketing Hub vs Deep Catalog）**：
   - 品牌聚合主页（如 `/bydauto/`）本质是 4S 店导购营销页，仅展示主推销售车系，特种皮卡、未公开概念车或独立子品牌往往被隔离在不同的路由体系下。

本文系统复盘 AutoVend 是如何通过**“三维立体动态自发现（Tri-Channel Dynamic Discovery）”**、**“全历年多 Payload 跨年份合并（Multi-Year Auto-Penetration）”**以及**“企业级零脚本 CLI 工具链”**，彻底解决上述完备性难题，实现与汽车媒体前台 1:1 像素级对账。

## 2. 三维立体动态自发现架构 (Tri-Channel Dynamic Discovery)

### 核心实现逻辑

在 `src/crawler/adapters/yiche_adapter.py` 中，爬虫每到一个品牌，自动并发穿透三大通道：

```python
async def discover_serials_by_brand(self, brand: BrandMeta) -> List[SerialMeta]:
    serials_dict: Dict[str, SerialMeta] = {}

    # 通道 1: 品牌聚合门户扫描 (Brand Hub)
    brand_hub_slugs = [brand.slug, CANONICAL_BRAND_SLUGS.get(brand.name, "")]
    for hub_slug in set(s for s in brand_hub_slugs if s):
        hub_url = f"https://car.yiche.com/{hub_slug}/"
        await page.goto(hub_url, wait_until="domcontentloaded", timeout=15000)
        # 动态抽取车系卡片与跳转代号

    # 通道 2: 官方 MID 选车工具大树穿透 (Master Tool Tree)
    if mid:
        url = f"https://car.yiche.com/xuanchegongju/?mid={mid}"
        await page.goto(url, wait_until="domcontentloaded", timeout=15000)
        # 递归提取带 /peizhi/ 入口的车系

    # 通道 3: 全站语义检索路由穿透 (Semantic Search Route)
    search_url = f"https://so.yiche.com/chexing/{urllib.parse.quote(brand.name)}/"
    await page.goto(search_url, wait_until="domcontentloaded", timeout=15000)
    # 捕获皮卡、方程豹子品牌、未命名概念车等长尾车型

    return list(serials_dict.values())
```

## 3. 全生命周期多 Payload 跨年份合并机制

针对前端 SPA 对多年款参数的异步分片加载问题，AutoVend 设计了基于网络响应拦截的多 Payload 聚合管线：

```
                      【多 Payload 跨年款合并管线】
 ┌───────────────────────────────────────────────────────────────────┐
 │ 进入车系配置页: https://car.yiche.com/{serial_slug}/peizhi/       │
 └─────────────────────────────────┬─────────────────────────────────┘
                                   ▼
        ┌─────────────────────────────────────────────────────┐
        │ 启动 Page.on("response") 监听 get_param_details     │
        └──────────────────────────┬──────────────────────────┘
                                   ▼
 ┌───────────────────────────────────────────────────────────────────┐
 │ 自动遍历年份选择器: 2026款 -> 2025款 -> 2024款 ... -> 【停售款】  │
 └─────────────────────────────────┬─────────────────────────────────┘
                                   ▼
        ┌─────────────────────────────────────────────────────┐
        │ 拦截捕获 N 个 JSON Payloads: [Payload_2026, ... ]    │
        └──────────────────────────┬──────────────────────────┘
                                   ▼
 ┌───────────────────────────────────────────────────────────────────┐
 │ _parse_multiple_api_payloads():                                   │
 │ 按 car_id 主键自动去重与属性合并，产出全息 RawSerialSpecSheet      │
 └───────────────────────────────────────────────────────────────────┘
```

## 6. 结语与工程启示

汽车数据工程不是简单的网络请求爬取，而是一场**与平台异构路由、工程立项代号、动态生命周期折叠的系统级博弈**。

AutoVend 团队通过：
1. **三维立体动态自发现** 彻底告别人工字典猜测；
2. **多 Payload 跨年份拦截合并** 彻底打破单一年款限制；
3. **企业级零脚本 CLI** 赋予团队即时查询、自愈重建与持续增量更新的能力。

这标志着 AutoVend 正式具备了为下一代汽车垂类智能 Agent 提供**全量、全息、高鲜度、自更新**工业级数据底座的核心能力。
