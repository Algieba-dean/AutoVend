# 脱敏层与语义路由层

一次对话在触达任何模型之前，先过两道关卡。本文说明各自的职责、**为什么是这个
顺序**、离线到在线的链路，以及每一处取舍。

## 全链路

```
用户消息
  │
  ├─ ① 语义路由（微秒级，无模型）
  │     锚点向量余弦相似 → 意图 + 家族
  │     控制流命中（"行，听你的"）→ 跳过抽取
  │
  ├─ ② PII 拦截（Presidio + 中文识别器）
  │     真实标识符 → 会话内占位符
  │
  ├─ ③ 混合推理（本地 8B ↔ 云端链）
  │     抽取走本地，合成走云端
  │
  └─ ④ 反脱敏
        抽取结果与回复中的占位符 → 还原真实值
```

三层成本阶梯：

| 层 | 代价 | 处理什么 |
|---|---|---|
| 语义路由 | **微秒**，一次矩阵乘 | 控制流轮次 |
| 本地 8B | ~65 ms TTFT | schema 约束抽取 |
| 云端 70B | ~1.7 s TTFT | 客户可见的推荐话术 |

## ① 语义路由

### 为什么排在脱敏之前

这是接线时踩过的坑，值得记下来。最初把脱敏放在前面，结果
「我叫陈晓明，手机13912345678，住上海市…」变成
`我叫<CN_PERSON_1>，手机<CN_PHONE_NUMBER_1>，<CN_ADDRESS_1>`——**占位符不携带语义**，
嵌入模型把它判成 smalltalk（0.650）并跳过了抽取，导致那一轮姓名没提取出来。

正确的理由：脱敏的威胁模型是「PII 不要发给第三方 API」。嵌入模型是**本地进程内**
的，不构成外泄。所以分类用原文，脱敏在其后。

另加一道保险：**含 PII 的轮次永不走快路径**。用户报姓名/电话时显然有可抽取内容，
分类器在这个方向上的自信是产品承受不起的。

### 离线：种子 → 聚类 → 锚点

```bash
uv run python -m src.semantic_router.build --probe
```

1. 种子语料（[src/semantic_router/seeds.py](../src/semantic_router/seeds.py)）
   131 条，分两个家族：
   - **控制流** `affirm` / `reject` / `defer` / `budget_objection` /
     `request_detail` / `smalltalk`
   - **需求流** `budget` / `powertrain` / `usage` / `category` / `brand` /
     `feature` / `constraint`
2. BGE-M3 嵌入（**复用检索栈的同一个实例**，不额外占显存）
3. 每个意图做球面 K-means（k=3），取簇心为锚点
4. 写出 `data/anchors.npz`：39 个锚点 × 1024 维 FP32

聚类而非保留全部种子向量的理由：去噪（离群种子不再自成一个吸引子），以及把在线
比对从 O(种子数) 降到 O(簇数)，整个矩阵留在 L2 cache 内。k>1 是因为意图本身多模态
——「太贵了」和「有没有便宜点的」都是预算异议但落在不同区域，强行合成一个簇心会
落在两者之间，谁都不靠近。

K-means 初始化用 argmax 而非随机采样，**构建是确定性的**：同样的种子重建出字节
一致的产物。锚点是提交物，非确定性构建会让每次重建都产生虚假 diff，真回归反而看不见。

### 在线：常驻张量

服务启动时加载为单个 FP32 tensor（**156 KB**），分类是一次
`(1,1024) @ (1024,39)` 矩阵乘加 argmax。BGE-M3 默认 L2 归一化，所以余弦相似就是
点积——代码里显式再归一化一次，让这个不变量不依赖别处的配置。

### 双重阈值

单一阈值不够。BGE-M3 把短中文句子压得很密，无关句子对某个锚点也能到 ~0.65。所以
同时要求**绝对分数 ≥ 0.62** 且**领先第二意图 ≥ 0.03**。

实测证据（`build --probe`）：

| 输入 | 分数 | margin | 判定 |
|---|---|---|---|
| 我再想想吧 | 0.925 | 0.224 | defer ✓ |
| 我要油车，不要电车 | 0.892 | 0.176 | powertrain ✓ |
| 行，听你的 | 0.830 | 0.092 | affirm ✓ |
| 今天天气真不错 | **0.704** | 0.019 | 未匹配 ✓ |
| 这个螺丝刀多少钱 | **0.654** | 0.004 | 未匹配 ✓ |

后两条**分数都过了 0.62**——拦下它们的是 margin。这就是双重阈值存在的原因。

### 命中后允许做什么

- **控制流命中**可以跳过抽取（`affirm` / `reject` / `defer` / `smalltalk`）。
  消息仍进记忆——生成器要读完整对话，只是没有可抽取的内容。
- **需求流命中不跳过任何东西**。它只是提示抽取器关注哪个槽位，抽取照跑。
  让路由自己决定需求，等于用「感觉像」替换掉「读完整句」。
- `budget_objection` 和 `request_detail` **刻意不在跳过列表里**：前者会修订预算槽位，
  后者可能点名具体车型。

## ② PII 拦截

### 中文识别器是必须自己写的

Presidio 内置识别器面向英文/欧美格式。对中文销售对话实测：

```
"我叫张伟，手机13888888888，身份证310101199001011234"
内置结果：姓名 ✗  手机 ✗  身份证 ✗   （只误报一个 URL）
```

所以 [src/privacy/recognizers.py](../src/privacy/recognizers.py) 定义了：

| 实体 | 方式 | 校验 |
|---|---|---|
| `CN_PHONE_NUMBER` | 正则，负向环视防止从长数字串里切出 11 位 | — |
| `CN_ID_CARD` | 18 位结构 | **GB 11643 校验位** |
| `CN_BANK_CARD` | 16–19 位 | **Luhn** |
| `CN_LICENSE_PLATE` | 常规 + 新能源 8 位 | — |
| `CN_PERSON` | **仅介绍句锚定**（"我叫X"/"我是X"） | 非名词黑名单 |
| `CN_ADDRESS` | 需含街道级单位（号/室/栋） | — |
| `EMAIL_ADDRESS` | ASCII 局部名（替换内置） | — |

校验位不是装饰。18 位数字串不等于身份证，Luhn 不通过的不是银行卡——没有这层校验，
拦截器会把任意长数字串都涂掉。

**姓名只做介绍句锚定，是有意的取舍**。中文自由姓名识别需要 NER 模型，而错判两个
方向代价都高：把「宝马」判成人名会毁掉检索查询，漏判则泄露姓名。锚定在介绍句上
保证精确率，漏的只是用户从未介绍过的名字。这个取舍由
[tests/test_pii_interceptor.py](../tests/test_pii_interceptor.py) 的
`TestNameDetectionLimits` 钉住。

内置 `EmailRecognizer` 被显式移除：它的 `\w` 局部名在 Unicode 下包含中日韩字符，
`邮箱zhang@example.com` 会被整体匹配，掩码连「邮箱」二字一起吃掉。

### 脱敏必须可逆

不可逆的涂抹会直接毁掉产品：Agent 要称呼客户姓名，试驾预约单上要写真实电话。所以
每个会话维护 占位符 ↔ 原值 的映射，从模型**抽取出来**的值在存储或展示前还原。
模型面对的是 `<CN_PERSON_a3f1_1>`，预约记录里是「张伟」。

两个必需性质：

1. **会话内稳定** —— 同一个值每轮映射到同一个占位符，否则第 3 轮引用的 token 和
   第 1 轮不是同一个，对话历史就不自洽了。
2. **跨会话不可解** —— 占位符带一个由 session_id 派生的短标签。没有它，每个会话都
   从 1 开始编号，A 会话的 vault 会愉快地解开 B 会话的 `<CN_PERSON_1>`，**把另一个
   客户的姓名静默填进回复**。session_id 传错时应当解不开，而不是解成错的人。

### 失败策略：fail open，但吵闹

识别器出 bug 不应该让整个对话崩掉，所以脱敏失败时消息原样通过——但记 ERROR 级日志，
因为一次未脱敏的轮次是真实的隐私事件。`/health` 里 `pii_interceptor` 的状态一眼可见。

## 运维

```bash
# 依赖
uv sync --all-extras
uv run python -m spacy download en_core_web_lg   # Presidio 需要注册一个 NLP 引擎

# 构建锚点（CI 也跑，--probe 不通过会 exit 1）
uv run python -m src.semantic_router.build --probe
```

`/health` 会报告两层状态。两者都 fail open：`disabled` 表示该轮走完整长路径，
即这两层出现之前的行为，不是服务故障。

```json
{
  "components": {
    "pii_interceptor": "ok",
    "semantic_router": "ok"
  }
}
```

## 已知限制

- **姓名召回率有意偏低**，见上文取舍说明。要提高需引入中文 NER，代价是误报风险。
- **锚点与嵌入模型绑定**。换 embedding 模型必须重建锚点，否则向量空间对不上，
  路由会静默劣化——加载时不会报错。CI 每次重建正是为此。
- **种子语料是手写的**。覆盖面来自作者对销售对话的判断，不是真实日志统计。有了
  线上数据后，应当从真实轮次里挖高频表达来替换或扩充。
- **遥测未覆盖快路径命中率**。目前只能从日志里看 `semantic fast-path`，还没有
  聚合到 `/telemetry/llm`。
